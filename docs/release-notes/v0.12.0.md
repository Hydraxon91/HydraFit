# HydraFit 0.12.0

Cloud planning moves to Groq, and the experimental on-device planner is gone. Offline planning is
unchanged and still the default.

## Cloud planning now uses Groq

- **Bring your own Groq key.** Add it in Settings → Groq API key, and Groq becomes selectable as a
  planning engine. The key is stored on this device, can be cleared at any time, and is never
  included in a backup.
- **Gemini is no longer offered.** A saved Gemini key is not reused and not sent anywhere. Plans you
  already saved keep the engine that generated them, and a stored Gemini selection plans with the
  built-in offline planner until you choose something else.
- Cloud planning sends your equipment, training goal and fatigue estimates to Groq. Sharing your
  logged weight history still requires the separate consent toggle, which stays off by default.
  Groq's own limits, charges and data policies apply to your account.
- Android only: iOS has no cloud key entry, so the offline planner is the only engine there.

## The on-device planner has been removed

- The experimental on-device model is gone, including its Settings import and remove controls, its
  storage row and its runtime. The built-in offline planner is unaffected.
- **An imported model file is deleted on first launch.** Only the two files HydraFit itself managed
  are removed and nothing else in app storage is touched. This frees several hundred megabytes for
  anyone who had imported a model.

## Fixed

- **An ambiguous exercise name no longer picks an exercise for you.** When a returned name matches
  more than one exercise you can do, that slot is dropped instead of guessed.
- **A missing Groq key is reported as a missing key**, not as an unusable AI response. Settings also
  keeps showing the saved cloud selection as unavailable rather than claiming the built-in planner
  is selected while planning cannot run.
- **A long retry request from Groq no longer reads as a rate limit** when the cause is a service
  outage.
- **Editing a guided workout's target applies to the remaining sets.** Only the fields you changed
  are applied; the rest of the prescription is left alone.
- **Clusters stay out of ordinary strength records and load progression.**
- **Weights-free prescription exports no longer carry nested loads.**
- **Values typed into the Logger keep their precision**, and recorded sets keep their own load
  meaning.
- **Editing or moving a scheduled workout keeps its prescription and cardio timing.**

## Upgrade notes

- Your history, plans, routines and settings are migrated in place. The only thing to re-enter is a
  cloud key, because the cloud engine now needs a Groq key.
- If you had selected Gemini, planning uses the built-in planner until you add a Groq key and select
  Groq.
- An imported on-device model file is removed during the first launch after updating.

## Known limitations

- Cloud plans are validated against your catalog and equipment, but they are still model output.
  Review a plan before you commit to it.
- Plan quality and latency depend on Groq's service. A per-day quota is reported without retrying.
- The Logger's pound/kilogram display round-trip remains a known gap; stored values are unaffected.
- On-device planning is no longer possible. There is no bundleable local model that meets the
  planner's quality bar, and the previous experimental path was removed rather than left unusable.
- This build was not re-tested as an in-place upgrade from the previous release; the data migration
  itself is covered by automated tests. If your history, plans or settings look wrong after updating,
  report it instead of starting over.
